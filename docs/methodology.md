# 复核方法说明

本文件说明工具如何把广告承诺、房型规则、房池库存与搜索证据组织成可审计的结论。
所有计算仅使用 Python 标准库，输入为 `data/` 下的八张 CSV。

## 1. 证据模型

每个基础抽样单位（折叠 `repeat_of` 后的一次抽样）最终得到六类互斥结论之一：

| 结论 | 含义 | 是否硬证据 | 计入履约分子 |
| --- | --- | --- | --- |
| `fulfilled` | 含全部应付费用、整户可接纳且含费价不高于广告承诺价 | 是 | 是 |
| `price_exceeded` | 明确搜到可订报价，但含费价高于承诺价 | 是 | 否 |
| `ineligible` | 搜索当日可见的房型规则拒绝该家庭组合 | 是 | 否 |
| `no_inventory` | 已查实房池关闭或房量为 0 的库存约束 | 是 | 否 |
| `timeout` | 服务接口未返回，没有可用核验信息 | 否（无法归类） | 否，进入非应答边界 |
| `out_of_scope` | 搜索条件超出广告覆盖（入住日、投放期、年龄上限） | 是 | 排除出该广告总体 |

短时售罄（`no_inventory`）、酒店拒绝组合（`ineligible`）、接口无返回（`timeout`）、
搜到偏高价（`price_exceeded`）是四种不同证据，任何合并口径都不得互相顶替。

## 2. 房型规则的搜索当日回看

同一 `room+hotel` 的规则可能有多个 `revision`。搜索日 `t` 可见的版本是同时满足

1. `valid_from <= t`；
2. `documented <= t`（搜索时已经登记，事后报送的版本当时不可见）；

的最高 `revision`。没有任何可见版本时，该报价不能按可接纳处理，记为 `ineligible`。
规则补录后重新复核历史抽次，仍然只使用搜索当日可见版本——现行规则只能用于界定
下一轮发布范围，不能改写当时的拒单结论。

家庭适配条件（对照可见版本）：

- `adults <= max_adults`；
- 儿童人数 `<= max_children`；
- 每名儿童年龄 `<= max_age`。

接口自报 `bookable` 但规则不适配时，以规则为准改判 `ineligible`；
接口自报 `ineligible` 时同样经规则复核后登记原因。

## 3. 应付费用与展示价履约

整住期应付价：

```
payable = nightly_bundle + mandatory_fee + 加床补费
加床补费 = 达到 mandatory_bed_age 的儿童人数 × bed_fee      （仅当 bed_included = no）
```

`bed_included = yes` 表示强制加床已含在展示价中，不重复计费。
只有 `payable <= max_price` 的可接纳报价才计 `fulfilled`；否则该单位为 `price_exceeded`。
因此"展示价只在含应付费用且确能接纳整个家庭时才算履约"。

## 4. 重复观测折叠

`repeat_of` 非空的抽次与基础抽次是同一次抽样的重复观测，折叠规则：

1. 任一观测出现达标履约报价 -> 单位 `fulfilled`（取最低含费价）；
2. 否则存在可订但偏高报价 -> `price_exceeded`；
3. 否则取最强硬证据（`ineligible` 优先于 `no_inventory` 优先于 `out_of_scope`）；
4. 全部观测均为 `timeout` -> 单位 `timeout`（无法归类，不是违约）。

典型情形：首次搜索 timeout、重复观测拿到 bookable，单位判履约而不是无法归类；
两次都 timeout 才进入非应答处理。重复观测不增加抽样权重，永远不被当作独立家庭。

## 5. 覆盖范围核对

每条基础抽次在估价前先对照广告承诺：

- 入住日落在 `arrival_lo ~ arrival_hi`；
- 搜索日（张贴时刻代理）落在 `running_from ~ running_through`；
- 儿童年龄不超过 `max_ages` 逐位上限，儿童人数不超说明。

不满足的单位记 `out_of_scope`，从该广告的估计总体中剔除并在对账表单列。
本资料中 S3 有 6 个 14 岁儿童抽次超出其 13|13 的适用上限，即按此处理。
广告声明 `pool` 与报价 `pool` 不一致、报价房型在规则表无任何版本，属于资料契约错误，
装载阶段直接报错。

## 6. 分层加权估计

层 `h` 的基础抽次数为 `n_h`，层人口为 `N_h`，单位权重 `w_h = N_h / n_h`。
已分类单位（排除 `timeout` 与 `out_of_scope`）上的加权履约率：

```
point = Σ fulfilled 权重 / Σ 已分类权重
```

分层比例的方差估计（有限总体修正）：

```
V = Σ_h W_h² (1 - f_h) p_h(1 - p_h)/(n_h - 1),  W_h = N_h / ΣN,  f_h = n_h / N_h
```

95% 抽样区间为 `point ± 1.96·√V`，层内已分类单位不足两个时该层方差保守取 0。

### 非应答（无法归类）边界

设已分类权重为 `C`、无法归类权重为 `U`、履约权重为 `F`：

```
下界 = F / (C + U)        # timeout 单位最终全部不履约
上界 = (F + U) / (C + U)  # timeout 单位最终全部履约
```

对外报告区间取抽样区间与非应答边界的**外包络**。承诺比例 `minimum` 的判定：

- 区间下界 >= 承诺：`met`（达标）；
- 区间上界 < 承诺：`not_met`（不达标）；
- 承诺落在区间内：`indeterminate`（证据不足，保留无法确定的区间，不得背书）。

总体结果之外，另按 `arrival_kind`（weekday/weekend）与 `family_kind`（small/older）
给出同样口径的分层拆分，用于识别可缩窄保留的人群或时段。

## 7. 联营联合覆盖

同一联营 `joint_scope` 的成员广告必须共用同一 `pool`，否则报错。
联合口径的机会去重键为：

```
(pool, arrival, availability_window, ages, adults, rooms)
```

两个入口（portal/hotel）对同一键的报价是同一可售机会，联合估计中只计一次，
冲突证据按"履约 > 偏价 > 不适配 > 无库存 > timeout"合并，含费价取最低。
联合分层人口在每个（入住分层, 团型）维度上取成员广告层人口的最大值作为并集上界，
避免把共享房池服务的同一批家庭重复计口。联合承诺 `joint_minimum` 在这组互不重复的
机会上按第 6 节同口径检验；成员单项 `minimum` 仍各自独立估计并同时列示。
分别评估两个入口会把仅一个家庭能订的房当成两个宣传口径各自可兑现，工具明确不采用。

## 8. 质检决定与已登记决定对账

| 估计结论 | 质检建议 | 说明 |
| --- | --- | --- |
| met | retain | 保留原承诺 |
| indeterminate | pause | 暂缓，对 timeout 抽次补搜后重判 |
| not_met 且存在达标子区间 | narrow | 缩窄到受支持的人群/时段 |
| not_met 且无达标子区间 | withdraw | 下架 |

`reviews.csv` 中已登记的 `approved/candidate/narrowed/withdrawn` 与当前建议逐条对账：
已核准但当前证据不支持、提案缩窄范围的独立估计未达标、已下架却被自动恢复等情形都会
输出冲突。缩窄一条联合广告后，必须以新范围重跑全流程，在同一组去重机会上重算
单项 `minimum` 与 `joint_minimum`，并复核共用库存支持的其余广告；只改页面措辞
不会使广告自动恢复上线。

## 9. 后送补证

| kind / explicit_value | 处理 | 影响分类 |
| --- | --- | --- |
| bed_confirmation / required | 仅当该抽次确有未计入展示价的强制加床时采纳，登记具体条款违反 | statistics（+clause_violations） |
| reserve_origin / pool_shared | 采纳，固化联营去重口径 | statistics |
| past_policy / not_visible | 驳回回溯适用；说明搜索当日可见版本与现行版本差异 | future_scope（仅影响下一轮范围） |

与证据不符的补证（如对没有加床义务的抽次送加床确认）驳回并记 `rejected`。
补证处理结果明确告诉收报人：被改变的是统计支撑、原广告确实违反的条款，
还是下一轮允许发布的范围；历史拒单判定不随补证而变化。

## 10. 抽样对账

报告中的对账表逐层列示：计划抽次、实际基础抽次、重复观测数、可验证结果数、
无法归类数、超范围数与层权重，保证抽样计划中的分层权重、重复抽取、可验证搜索与
无法归类搜索彼此对得上。162 个基础单位对应 186 条抽次记录（24 条重复观测），
折叠前后数量在对账表与 JSON 输出中均可复算。
